# TK-953 实现权限分级与高风险人工确认门禁

- Status: done
- Priority: P0
- Project: `automation-v1`
- Sprint: `sprint-001`
- Owner: Security
- Due: 2026-03-23
- Depends On: `TK-951`, `TK-952`

## Goal

让自动化执行具备安全边界：根据权限级别和风险类别决定自动继续、暂停确认或直接阻断。

## Deliverables

1. 权限分级模型（只读/可编辑/可执行检查/可提交/可推送）
2. 高风险操作识别规则（文件、命令、改动类型）
3. 非交互与交互模式下的门禁处理逻辑
4. required-surface 策略（哪些阶段必须由指定 surface 执行）

## Acceptance

1. 高风险动作在非交互模式下默认失败并给出明确提示。
2. 交互模式可以触发人工确认点并记录确认结果。
3. 策略判断结果可被 `run` 输出和审计日志消费。
4. 对 required-surface 阶段，preflight 失败时会触发暂停或阻断策略。

## Notes

1. 高风险目录与操作范围需与 PRD 权限边界保持一致。
2. 已在 `run` 流程中新增 `policy-gate` 阶段，默认串联为 `preflight -> policy-gate -> process stages`。
3. 已实现权限分级解析（`read/edit/check/commit/push`）与动作权限校验，支持从 route 与输入内容推断所需动作。
4. 已实现高风险识别规则（文件/命令/改动类型）并在 `--non-interactive` 下默认阻断，在交互模式下返回 `pause_for_approval`。
5. 已支持 `--approve-risk <tag>` 显式确认高风险标签，并在 `run` 输出中写入 `policy` 决策详情供审计消费。
6. 已补齐 required-surface 门禁策略：preflight 对缺失入口按交互模式输出 `pause_for_approval` 或 `block`。
7. 已将通用工具函数抽离到 `src/commands/automation-shared.js`，并新增 `test/commands/automation-shared.test.js` 保障复用稳定性。
