# TK-954 实现自动化执行审计日志与恢复检查点

- Status: done
- Priority: P1
- Project: `automation-v1`
- Sprint: `sprint-001`
- Owner: Platform
- Due: 2026-03-24
- Depends On: `TK-952`, `TK-953`

## Goal

为自动化执行补齐可追踪和可恢复能力，确保每次执行都有完整轨迹，并在失败后可定位与接管。

## Deliverables

1. 自动化执行审计日志模型与落盘规范
2. 阶段级检查点记录机制
3. 失败回放与恢复入口的最小接口

## Acceptance

1. 每次 `run` 产生唯一执行记录并落盘到报告目录。
2. 审计结果至少包含阶段状态、门禁判断、关键动作和失败原因。
3. 在 `assisted` 模式可基于检查点执行恢复或人工接管。

## Notes

1. 审计结果需兼容现有 `report` 输出模型，避免形成平行体系。
2. 已在 `run` 增加唯一执行编号与审计落盘：每次运行写入 `automation.audit.outputDir`（默认 `.repo-ai-governor/reports/runs`）并更新 `latest-run.json`。
3. 已补齐阶段级 checkpoint：输出 `checkpoints.stages`（阶段状态、耗时、门禁结果、关键 details/outputs、warnings、error）。
4. 已补齐失败恢复最小接口：新增 `--resume-from`、`--resume-stage`（assisted 模式），支持从审计记录恢复并对已通过阶段执行 checkpoint restore。
5. 审计结构保持与 `report` 兼容：`run` 输出与落盘记录均为统一 JSON 载荷，可直接被 report/source 读取归一。
