# TK-956 输出编排解释结果（默认/自定义）

- Status: done
- Priority: P1
- Project: `automation-v1`
- Sprint: `sprint-001`
- Owner: Core Runtime
- Due: 2026-03-26
- Depends On: `TK-952`

## Goal

让 `run` 的结果可解释：明确本次执行是默认流程还是自定义流程，并输出已生效的编排结构，便于排障与团队协作。

## Deliverables

1. `run` 输出新增流程来源字段（`default | customized`）。
2. `run` 输出新增编排快照字段（生效阶段、review loops、taskLoop 绑定阶段）。
3. 编排快照覆盖默认流程与用户覆盖流程两种场景。
4. 对应测试覆盖（命令测试 + 配置组合测试）。

## Acceptance

1. 未配置 `automation.process` 覆盖时，输出中可看到 `process.source=default`。
2. 配置了 `automation.process` 覆盖时，输出中可看到 `process.source=customized`。
3. 输出中的 loops 与路由键和实际执行一致，不出现空洞或冲突字段。
4. 新增字段兼容现有 `json/markdown` 输出格式，不破坏老字段。

## Notes

1. 该任务不改变业务流程顺序，只增强可观测性与可解释性。
2. 已在 `run` 输出新增 `process.source`（`default | customized`）与 `process.snapshot`（stages/reviewLoops/taskLoop/routeDefinitions/workflow stageOrder）。
3. `process.source` 判定已从“是否存在 process 字段”升级为“是否相对默认流程存在有效差异”，避免默认初始化误判。
4. 已补齐回归测试（默认/自定义流程来源、快照结构一致性）。
