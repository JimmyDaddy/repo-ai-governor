# TK-3001 收敛 TS-only 白名单并扩展关键目录审计边界

- Status: in-progress
- Priority: P0
- Project: `ts-vitest-v1`
- Sprint: `sprint-003`
- Owner: Release
- Due: 2026-04-08
- Depends On: `TK-2006`

## Goal

将 TS-only 审计从“初步可用”提升为“长期可维护”，明确白名单字段语义、责任归属与目录边界策略。

## Deliverables

1. 更新 TS-only 白名单配置结构与字段说明文档
2. 明确 `src/test` 之外需要纳入审计或显式豁免的目录策略
3. 明确导入路径策略：相对导入显式扩展名、非相对导入禁止 `*.js/*.mjs/*.cjs`
4. 输出当前 JS 白名单清单与每项保留理由

## Acceptance

1. 审计配置可直接解释“为什么允许该 JS 文件”
2. 新增非白名单 `.js` 可被稳定识别并阻断
3. `npm run check` 与 `npm run release:ga-check` 通过

## Progress

1. 已在 `check-esm-import-specifiers` 门禁中增加“非相对导入禁止 `.js/.mjs/.cjs` 后缀”校验，覆盖 `pkg/subpath.js` 风险场景。
2. 已在 `AGENTS.md` 增加 `code_standards.md` 入口要求，明确 AI 执行前必须读取并遵循代码规范。
3. 已新增治理回归测试 `test/governance/esm-import-specifier-gate.test.ts` 验证导入规则通过/失败分支。
4. 已新增动态依赖加载门禁 `scripts/governance/check-dynamic-import-usage.js`：默认禁止 `import()/require()`，例外需在代码附近添加 `// dynamic-import-allowed: reason` 注释。
5. 已在现有确需动态加载场景补充例外注释（`bin` 入口动态导入、examples 动态模块加载、CLI/commands 读取 `package.json`），并新增 `test/governance/dynamic-import-usage-gate.test.ts` 回归验证。
6. 已新增有限集合字面量治理门禁 `scripts/governance/check-finite-literal-sets.js`：默认要求有限集合定义集中在 `src/constants`，一次性局部判断可通过 `// literal-set-allowed: reason` 注释保留。
7. 已新增 `scripts/governance/literal-set-whitelist.json` 记录存量迁移清单，并将技能动作集合迁移到 `src/constants/skill-actions.ts` 作为首批收敛示例。
8. 已新增工具函数复用评估门禁 `scripts/governance/check-utils-reuse-governance.js`：新增 `src/utils` 导出函数必须在 `execution_notes` 中记录复用评估结论，且禁止重复函数名散落。
9. 已新增类型治理门禁 `scripts/governance/check-type-governance.js`：对象结构契约禁止 `type Xxx = { ... }`（例外需 `// type-shape-allowed: reason`），并要求新增 `interface/type` 声明放置在 `src/types/interfaces/*.interface.ts` 与 `src/types/aliases/*.type.ts`，同时保留存量迁移白名单 `scripts/governance/type-governance-whitelist.json`。
