# TK-3004 建立覆盖率基线并引入阈值门禁

- Status: completed
- Priority: P1
- Project: `ts-vitest-v1`
- Sprint: `sprint-003`
- Owner: QA
- Due: 2026-04-11
- Depends On: `TK-3003`

## Goal

形成覆盖率“可观测 + 可约束”机制，为核心模块设置最低阈值并纳入质量门禁，避免回归时覆盖率静默下滑。

## Deliverables

1. 输出核心模块覆盖率基线快照
2. 定义全局或分层覆盖率最低阈值策略
3. 将覆盖率阈值校验接入门禁命令

## Acceptance

1. `test:coverage` 结果可被门禁消费
2. 阈值配置可解释且与当前基线匹配
3. 覆盖率低于阈值时可明确失败原因

## Progress

1. 已输出覆盖率基线快照文档 `docs/ts-vitest-v1/sprint-003/coverage-baseline.md`，包含全局与核心目录覆盖率指标。
2. 已新增阈值配置 `scripts/ci/coverage-thresholds.json`，采用“全局阈值 + 核心目录阈值”双层策略。
3. 已新增阈值校验脚本 `scripts/ci/check-coverage-thresholds.js`，失败时可输出 scope/metric/expected/actual 明细。
4. 已接入门禁命令：新增 `check:coverage-thresholds`、`check:coverage`，并将 `ci:quality` 升级为 `typecheck -> check -> check:coverage`。
5. 验证通过：`npm run check:coverage-thresholds`、`npm run check:coverage`、`npm run ci:quality` 全部通过，TK-3004 完成。
