## Goal

在发布与运行时链路中，明确“必须保留的 JS 文件”最小集合，并建立对应审计规则与维护责任。

## Deliverables

1. 发布/运行时 JS 文件白名单清单（含用途与归属）
2. 白名单与 `dist` 产物边界约束说明
3. 对应自动审计或发布前检查增强

## Acceptance

1. JS 保留边界可通过脚本自动核对
2. 新增无归属 JS 文件会触发门禁告警
3. 发布链路验证保持通过

## Progress

1. 已新增发布包 JS 白名单配置 `scripts/release/runtime-js-whitelist.json`，按 `dist` 边界与非 `dist` 显式路径分别维护 `owner/purpose`。
2. 已新增审计脚本 `scripts/release/check-runtime-js-whitelist.js`，通过 `npm pack --dry-run` 核对打包 JS 文件，未命中白名单将直接失败。
3. 已将脚本接入发布前检查：新增 `check:runtime-js-whitelist` 并挂载到 `release:check`，同时补充 `test/release/release-distribution.test.ts` 回归。
4. 已沉淀边界说明文档 `docs/ts-vitest-v1/sprint-003/release-runtime-js-whitelist.md`（包含用途、归属与验证命令）。
5. 已新增负向回归（`test/release/release-distribution.test.ts`）验证“未归属非 `dist` JS 必须失败”，并完成发布候选链路复验：`npm run release:candidate` 通过（含 `ci:quality`、`release:check`、`release:verify-local`），TK-3005 结项。
