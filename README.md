# Repo AI Governor

[English](./README.md) | [简体中文](./README.zh-CN.md)

`Repo AI Governor` is a repository-local CLI for plan-first AI engineering governance.
It keeps execution artifacts, review lifecycle, and quality gates aligned across tools.

## What It Solves

1. Enforce plan-first execution (`plan -> implement -> check -> review -> verify`).
2. Keep sprint artifacts consistent (`plan.md`, checklist, CSV ledger, task cards, CR files).
3. Provide executable governance gates instead of text-only process docs.
4. Orchestrate multi-stage automation with stage routing and checkpoint resume.
5. Reuse one governance model across `Codex`, `GitHub Copilot`, and `Claude Code`.

## Install

Node.js `>=18` is required.

```bash
# run without installation
npx @cjhdev/repo-ai-governor --help

# or install as dev dependency
npm install --save-dev @cjhdev/repo-ai-governor
npx repo-ai-governor --help
```

Package name and CLI command are different:

1. Package: `@cjhdev/repo-ai-governor`
2. Command: `repo-ai-governor`

## 10-Minute Flow

```bash
TMP_DIR="$(mktemp -d /tmp/repo-ai-governor-demo.XXXXXX)"
CLI="npx @cjhdev/repo-ai-governor"

# 1) bootstrap governance files
$CLI init \
  --cwd "$TMP_DIR" \
  --project demo \
  --sprint sprint-001 \
  --adapter codex \
  --locale en-US \
  --format json

# 2) validate workspace baseline
$CLI doctor \
  --cwd "$TMP_DIR" \
  --project demo \
  --sprint sprint-001 \
  --strict \
  --format json

# 3) create requirement and generate plan + task artifacts
cat > "$TMP_DIR/request.md" <<'EOF'
# Requirement
Build a repository governance demo flow.
EOF

$CLI plan \
  --cwd "$TMP_DIR" \
  --project demo \
  --sprint sprint-001 \
  --input "$TMP_DIR/request.md" \
  --title "Repository governance demo flow" \
  --format json

# 4) run governance checks for this sprint
$CLI check \
  --cwd "$TMP_DIR" \
  --project demo \
  --sprint sprint-001 \
  --write-report \
  --format json
```

Generated outputs include:

1. governance config and execution context files (auto-managed by the tool)
2. `AGENTS.md`
3. `docs/<project>/<sprint>/plan.md`
4. `docs/<project>/<sprint>/tasks/*`
5. `docs/<project>/<sprint>/code-review/*`

Full walkthrough: [Quick Start](./docs/quick-start.md)

## Use With AI Tools

Install skills by surface:

1. `codex` -> `.codex/skills/`
2. `github-copilot` -> `.github/skills/`
3. `claude-code` -> `.claude/skills/`

```bash
npx @cjhdev/repo-ai-governor skills list --surface codex --format json
npx @cjhdev/repo-ai-governor skills install --surface codex --format json
npx @cjhdev/repo-ai-governor skills doctor --surface codex --strict --format json
```

After installation, ask your AI assistant to:

1. read `AGENTS.md` and the current-context file generated by `init`
2. execute with installed skills (for example `$governor-plan-runner`, `$governor-task-implementer`, `$governor-delivery-finisher`)

## Core Commands

1. `init`: bootstrap governance config and sprint structure.
2. `skills`: list/install/doctor official skills.
3. `doctor`: validate environment, config, and layout.
4. `plan`: generate plan and task artifacts from a requirement.
5. `check`: run governance checks by stage or changed-only scope.
6. `run`: orchestrate multi-stage automation with preflight + stage routing + resume.
7. `review`: generate code review records.
8. `review-verify`: append re-check results and advance CR status.
9. `report`: render governance output into summary/markdown/json.
10. `upgrade`: upgrade generated config/templates safely.

### `run` Highlights

1. `--routing-profile` and `--route <stage=surface>` for stage-level routing.
2. `--explain-process` for compiled process preview.
3. `--validate-process` for process-only validation without stage dispatch.
4. `--resume-from` and `--resume-stage` for assisted recovery from checkpoints.
5. `--approve-risk <tag>` for explicit high-risk approvals.

## Review Lifecycle

Default file lifecycle:

1. `review_<slug>.md`: review generated, pending verification
2. `verified_review_<slug>.md`: verification completed
3. `resolved_review_<slug>.md`: accepted findings resolved

Development baseline:

1. `npm run typecheck`

3. `npm run check`

Release baseline:

1. `npm run ci:quality`

## Governance Baseline In This Repository

This repository is running under a TS-first + Vitest + Biome hardening baseline:

1. Source and tests are TypeScript-first with whitelist-governed JS residue.
2. `npm run check` enforces formatter + linter + build + standards gate.
3. `npm run ci:quality` adds typecheck + coverage threshold checks.
4. `npm run release:ga-check` is the release-ready gate chain.
5. `code_standards.md` currently enforces `CS-001` to `CS-014`.
6. Monorepo naming gate script is prepared at `scripts/governance/check-monorepo-naming.js` and intentionally kept out of active verification commands for now.

For closure details and long-term operation rules, see:

1. `docs/ts-vitest-v1/sprint-003/migration-closure-report.md`
2. `docs/governance/long-term-maintenance-guide.md`

## Customize Standards And Project Rules

`governor.yaml` supports both standards and slot-based customization:

```yaml
standards:
  preset: official/base
  overrides:
    quality:
      tests: required
slots:
  enabled:
    - security-review
```

Project-specific slot files are generated and managed by the tool's governance workflow.

If your team already has a `code_standards.md`, define `## Verification Commands` and run:

```bash
npm run check:code-standards
```

Recommended flow for adding a new code standard:

1. Add a numbered rule under `## Non-negotiable Rules` (for example `- [CS-005] ...`).
2. Add one or more executable commands under `## Verification Commands`.
3. Run `npm run check:code-standards` locally and verify the gate passes.
